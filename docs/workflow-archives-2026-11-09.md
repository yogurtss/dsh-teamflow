# 人工返工分支与成果归档（dev）

本次开发版本沿用 `0.2.8-dev.1`，不提升 main。成果归档是一种流程节点，和结束／归档整个团队是两个操作。

## 门控与返工

- 画布和模板预览共用圆角菱形。人工审核使用琥珀色，AI 门控使用紫色，状态、审核模式和轮次分开显示。左右顶点与连接端口保持一致。
- 普通人工审核提供「通过验收」和「创建返工分支」。选择上游返工起点并填写意见后，一次操作保存本轮材料、决定与意见，再复制该任务及其受影响的后续步骤，接回原检查点。原任务及输出保留，新结果仍需人工验收。不能跨越另一检查点复制返工路径。
- 循环审核保持 PASS／REJECT：修改原循环节点，不新增返工节点。轮次上限、超时暂停、追加有限轮次继续、历史查看沿用已有循环协议。普通流程不强制设置循环。

## 成果归档节点

在画布点击「成果归档」，填写要求、连接上游、完成配置，再按流程启动。节点由系统执行，不分配 Agent，不调用模型。建议连接最终交付任务或已通过的人工审核；循环场景必须放在 PASS 之后，不允许置于循环体内。

默认生成不可变 JSON 清单，包含上游任务与执行版本、输出、验证记录、人工评审快照、循环运行／轮次／历史索引、当前文件 SHA-256 和可用的 Git HEAD。Git HEAD 只作引用，不表示工作区干净，也不表示归档动作重新验证了成果。

配置项：

- `copyFiles: false` 默认只保存清单与引用；启用后复制文件。
- `paths: []` 默认使用上游声明的 `changedPaths` 和 `deliverables`；填写后使用指定的工作区相对范围。没有声明文件时仍会保存任务成果与证据，不会自动扫描整个工作区。
- 文件范围沿用已有成果读取规则，最多 200 项；副本总量最多 100 MiB；清单最多 20 MiB。不存在的文件明确记录为缺失，不计入副本；不可读、范围不完整、越界及复制过程中的文件变化都会失败，不标为归档成功。副本不接受符号链接。

文件保存在团队目录的 `artifacts/<归档版本 UUID>/manifest.json` 和 `files/`。节点侧栏可以展开成果、验收记录、文件摘要，下载完整清单。每次成功归档保留独立版本，重跑不会覆盖旧清单或副本；整个团队归档及恢复时一并保留。模板只保留节点类型和配置，不带执行记录。

归档在独立 Worker 线程扫描、哈希和复制，30 秒超时；调度只在短暂团队锁内领取／提交状态。暂停或重跑撤销旧尝试，旧线程不得提交完成，未发布的临时副本清理掉。中断恢复使用新执行代次。没有权限的会话不能读取归档，客户端不能指定任意清单路径。

## 模型接口

`agent_teams_create.plan.tasks[]` 和工作流 `add_task` 支持 `kind: "archive"`、`archive: { copyFiles, paths }`。不设置 `assignee` 或 `checkpoint`。普通 `update_task` 和 `rerun_task` 可调整归档配置；执行 Agent 不能领取、改写或伪造系统归档完成。

例如：

```json
{"action":"add_task","id":"archive-results","kind":"archive","subject":"保存成果","description":"保存已通过审核的成果清单与证据引用。","dependencies":["delivery"],"archive":{"copyFiles":false,"paths":[]}}
```
