# 按需验收与大文件边界

开发版本变更（2026-11-09）：普通 `/state` 卡片轮询只读取团队状态和成员活动，不再枚举、stat 或散列交付物。界面显示的是已保存的任务/审批状态，不是对当前文件重新验收的结论。打开或刷新验收材料才读取产物；提交审批时重新读取当前证据，不能复用预览缓存代替正式校验。

验收材料的文件读取在独立 worker 中执行，最多 32 个在途请求，3 秒超时后终止 worker、释放等待请求，下次显式请求可重建。相同在途请求合并。打开材料可复用最多 1024 条、5 秒 TTL 的哈希缓存；复用前检查真实路径、设备、inode、大小、mtime 和 ctime。审批提交默认绕过缓存。目录列表不缓存。

自动内容审计仅覆盖常见源码、文本、配置、图片和文档类型，以及 Dockerfile、Makefile、LICENSE 等常用无扩展名文件。权重、压缩包、可执行文件和未知格式不读取内容。单文件上限 2 MiB，每次 scope 读取上限 32 MiB，仍保留 200 条路径上限，并限制每次最多检查 10,000 个目录项。直接声明的文件与目录展开结果遵循相同限制。被限制文件保留路径、大小、修改时间和未审计原因，不会生成全文件哈希，也不会作为已验证证据；以独立 skipped 状态列出，请用户在本机检查。策略跳过不会升级为读取错误或证据失效；真正的删除、读取错误和范围枚举不完整仍单独处理。归档复制模式对这些文件只保存元数据。

成果预览与验收指纹分开：大文本、日志、CSV 最多读取开头 256 KiB，界面明确标注截断，不提供整文件指纹；UTF-8 截断边界不显示损坏字符。图片保持 4 MiB 预览上限，不支持的文件只展示元数据。所有预览仅在打开文件时触发。

团队状态组装失败时状态接口返回 503，前端保留最近成功的卡片，不以缺少团队的成功列表伪装删除。真正删除/归档仍按原流程更新。

验收指纹仅绑定已审计内容、任务报告与排除边界，不绑定修改时间或跳过文件的字节数。兼容 0.2.8 旧记录中的策略拒绝原因；这些记录不再被当作真正的 I/O 失败。

回归覆盖：110 个权重文件零内容读取、单文件和总预算、TTL 命中/过期/修改/工作区隔离、正式读取绕过缓存、普通卡片零产物读取、损坏状态不返回删除、后台超时、截断预览及现有审批证据变更检查。尚未在用户实际 55 秒场景的 DSH 实例中测量修复后的端到端延迟。
