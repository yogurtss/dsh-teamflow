## 发现与改进点

1. **已修复测试脚本误报。** 原脚本要求需求文档必须出现字面量 node:test，本次合法文档写的是 node --test。在第一组并行完成后修正判断，并从同一已保存队长会话恢复。没有重做适配或创建重复节点。保留失败记录 previous-result.json。恢复选项只支持分析已结束、人工方案关卡尚未批准的这一阶段。
2. **模型参数误用被正确拦截。** 一次 agent_teams_update_task 给活动任务填写了仅用于结束任务的 evidence_note。服务端拒绝后模型自行纠正；未发现错误状态被写入。
3. **文件范围约束未完全遵守。** reviewer 在代码调查时通过 shell 在系统临时目录创建、执行并删除了小型 ESM 探针。模型报告和工具轨迹均记录该行为，但它违反了用例“只在本测试工作区内修改”的要求。这是模型执行边界问题，不能计为范围合规通过。应优先用不落盘探针，或在任务允许的工作区子目录准备探针；需要强制边界时须验证 OS 沙箱，而不能只依赖提示词。本轮沿用前次专用测试 Profile 的 danger-full-access，未修改产品默认权限，也未声称有 OS 沙箱隔离。
4. **小任务开销仍偏大。** 代码审查约 75 秒，交付汇总约 48 秒；不同角色重复运行了部分相同测试。独立复核有价值，但可按复杂度限制文档与探针数量，避免增加流程节点后花更多时间在汇报上。本次没有因此修改模板或“结论已过期”文案。
