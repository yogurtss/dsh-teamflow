# 功能开发模板真实工作流试跑（2026-10-31）

本次用例是在空工作区实现 `validatePort(value)`：只接受 1–65535 的原始 number 整数，其他输入返回 false，不做类型转换、不抛异常。交付 `requirements.md`、`validator.mjs`、`validator.test.mjs`，不增加依赖。

流程为内置「功能开发」的原始五节点：需求分析 → 人工确认需求 → 实现与自测 → 独立验证 → 人工最终验收。模型使用现有 DeepSeek 账号的 `deepseek-flash` / high；宿主固定为 Harness `0.2.1-rc.2`，插件从打包产物加载。没有用脚本模拟模型回答或成员执行。

## 发现与修复

1. **已修复：长提案重复 JSON 编码容易失败。** `0.2.5-dev.1` 的适配工具把 operations 声明为 JSON 字符串。真实模型连续两次遗漏对象闭合括号，工具分别在字符 1823、1554 拒绝解析，第三次才成功。原子校验保护了原字段，但整批重复生成增加了等待。`0.2.5-dev.2` 改为结构化数组，声明 action、两层任务等字段；保留整批校验、体积限制、固定模板结构和人工确认。增加了模型可见工具契约快照。
2. **环境阻塞：Windows 沙箱 ACL。** 首次带 workspace-write 沙箱的运行连列目录/Node 版本命令都未启动，Agent 报告 ACL provisioning error。保留该次记录并终止，不计为通过。后续只在专用测试 Profile 中采用 Harness 的 danger-full-access 预设；不改变项目产品默认权限。工作目录是新建的，但本次成功运行不证明 Windows OS 沙箱可用。
3. **建议优先改善：验收文件可读性。** 验收上下文目前提供上游报告、文件大小/指纹等材料，验收 Agent 不具备读取完整交付文件的工具。真实需求验收因此要求用户再打开原文核对部分条款。建议后续提供只读、限交付范围、分页且带版本指纹的文件读取入口，继续保留用户最终批准权。
4. **建议改善：适配进度与轻量任务成本。** 页面仅显示“AI 正在思考”，不易区分长时间生成、工具重试和等待确认。旧版本次还生成了约 17 KB 的需求文档和 22 条验收项，对小函数明显偏重。建议展示当前阶段/耗时，并让模板要求按任务复杂度控制文档和清单长度；不要因此省略必要边界验证。

修复后的 85 项相关自动测试、最终打包宿主流程、工具契约快照和冷启动恢复均通过。最终包的 workflow-native.js 与真实模型试跑时加载的代码指纹一致。

## 验证边界

通过真实鉴权 HTTP 路由模拟用户操作；两次人工批准由测试驱动完成，不代表 AI 自行批准。核对原字段更新、通用层/拓扑不变、确认前不执行、需求关卡前不存在实现、已批准规格不被后续改写。外部断言重新导入生成的模块，覆盖 20 个有效/无效输入，并重新执行 Agent 生成的 node:test 文件。

这不是浏览器点击/视觉验收，也没有覆盖其他服务器、其他模型、并发团队及算子 GPU 性能。一次通过不代表模型永不犯错。模板保存/版本隔离、重复确认、拒绝/重做、讨论重启恢复由独立的确定性打包宿主回归验证。

## 复跑

先按项目方式 build / pack，再准备打包宿主并运行：

```powershell
node scripts/template-runtime-verify.mjs output/yogurtss-dsh-teamflow-0.2.5-dev.2.tgz output/workflow-runtime-new
node scripts/feature-workflow-verify.mjs output/workflow-runtime-new/runtime output/feature-trial-new "$env:USERPROFILE/.dsh/.credentials.yaml"
```

需要本机可用的 DeepSeek 账号和已安装的固定 Harness 依赖。脚本只引用凭据文件路径，不输出或复制凭据值；Profile、会话、模型调用记录和生成代码保存在指定的新报告目录。每次使用全新目录，最多 70 次模型调用、20 分钟总时限。请在本地查看 `result.json`、`trace.jsonl`、`external-test.txt` 和 `workspace/`。这些运行态记录不提交 Git。
