# Super Agent on dev

The workspace supervisor follows the DeepSeek Harness research prototype's separation of intake, attention and execution. TeamFlow owns workflow execution and all human decisions.

Subscriptions default to off. Completing a workflow expires an ordinary subscription in the same persisted update, including while the browser is closed. An explicit keep setting retains it across reruns. A completed checkpoint within a continuing workflow removes only its resolved reminder. Approvals, plan changes and dispatch use the existing workflow controls.

## Asynchronous coordination design

The sidebar opens the current global conversation. A per-conversation read cursor survives host restarts. Opening the current chat acknowledges incoming entries through the sequence fetched for that view. Settings and archived chats leave the cursor alone. Revisions of a card share one unread slot. Clearing context creates a new native session and keeps previous transcripts available for review.

The global conversation receives watch cards and queries subscriptions through `teamflow_watched_workflows`. A direct human instruction can call `teamflow_forward_requirement` with a named target and a verbatim requirement. Lookup occurs on demand across registered projects and rejects ambiguous matches. Scheduled notices cannot initiate a handoff. The request ID ties the human message and target to a durable outbox entry, a Captain mailbox receipt per round and one global chat card.

The background worker wakes the recorded Captain independently of the Web panel. The Captain reports a result, asks a question, or registers delegated work through `teamflow_report_requirement`. A plain Captain reply is labeled as such. The user can answer a question on the card or via `teamflow_answer_requirement` in the main chat. Each answer advances the round and rejects stale replies. Delivery resumes after a host restart. Results go to the current global conversation and use the existing unread mechanism. The relay does not apply workflow approvals.

The design article assigns cross-task decisions to a persistent Router and allows an entire agent team to serve as a Worker. A TeamFlow run already has an appropriate execution owner in its Captain. The public prototype narrows the article's design to a repository and routes assessed work through a domain engine. | Persist routing decisions and pending deliveries together. Return a receipt immediately. Deliver results or questions later, with correlation to their source. Recheck ownership and attempt IDs on recovery. | [Transactional engine](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/src/core/engine.ts), [effect queue](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/src/app/effects.ts), [delivery](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/src/app/delivery.ts) |

The management regression covers routing to one of two workflows, one Captain mailbox receipt per round, recovery, and returning a question and result on the same card. Cross-workflow handoff and initiating new plans remain possible extensions.
