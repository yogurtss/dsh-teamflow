# Super Agent on dev

The workspace supervisor follows the DeepSeek Harness research prototype's separation of intake, attention and execution. TeamFlow owns workflow execution and all human decisions.

The settings picker enumerates available workflows on demand. The team record owns its subscription. |
| [reportRelay](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/app/notices.ts) filters routine progress and gives a human question a stable identity. | Pending proposals use their proposal ID. Checkpoints use task, run and round. Configuration, rerun, returned review and paused-loop blockers retain their reason. Restoring a Web tab derives open items from current persisted state. |
| [AgentDelivery](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/app/delivery.ts) checks request identity before delivering to a session. | A stable item identity groups repeated observations. Web reminder display is remembered per browser profile and workspace. The model reads current records when the user asks a question. |
| [Overview and navigation](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/6337fc823ce20251c8de8085948165c81aaa701e/src/client/app.tsx) expose a management panel, concrete records and the main session. | A separate sidebar entry opens the supervisor. A retained captain session hosts the original workbench for each reminder. One global conversation per Harness home reads explicitly watched workflows across registered projects. Subscriptions default to off. Completing a workflow expires an ordinary subscription in the same persisted update, including while the browser is closed. An explicit keep setting retains it across reruns. A completed checkpoint within a continuing workflow removes only its resolved reminder. Approvals, plan changes and dispatch use the existing workflow controls.

## Asynchronous coordination design

The global conversation currently receives attention cards and reads subscribed workflow summaries. Its only model tool is `teamflow_watched_workflows`. Workflow state determines when cards open and close. A user's new instruction in the global conversation currently has no delivery path to a Captain.

The design article assigns cross-task decisions to a persistent Router and allows an entire agent team to serve as a Worker. A TeamFlow run already has an appropriate execution owner in its Captain. The public prototype narrows the article's design to a repository and routes assessed work through a domain engine. [Design article, sections 2–4](https://mp.weixin.qq.com/s/zoS7GlReWPhfCjENGxXCdg) · [Prototype scope](https://github.com/deepseek-ai/dsh-superagent-prototype)

| Design decision for a future iteration | Implementation reference |
| --- | --- |
| Preserve the original input, its source, stable ID, project and explicitly granted scope. Let code deliver a follow-up with known ownership directly. Give the Router ambiguous or unowned work to assess. | [Intake](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/src/core/intake.ts), [assessment](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/src/app/assessment.ts) |
| Give the Router narrowly scoped tools to attach a user's instruction to an existing run, initiate a new planning draft, request a status report and send relevant context between runs. The Captain executes within the existing workflow and can return an out-of-scope message for reassessment. | [Main-session tools](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/src/app/tools/main.ts), [follow-up ownership](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/002-authorization.md) |
| Persist routing decisions and pending deliveries together. Return a receipt immediately. Deliver results or questions later, with correlation to their source. Recheck ownership and attempt IDs on recovery. | [Transactional engine](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/src/core/engine.ts), [effect queue](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/src/app/effects.ts), [delivery](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/src/app/delivery.ts) |

The first management test should send a real scope change to workflow A while workflow B runs, then query B before A finishes. Verify A's Captain received the original instruction, its subsequent execution reflects that instruction, B remains responsive, and replay after a restart causes a single delivery. Add cross-workflow handoff once this round trip works. Observation subscriptions, user-authorized actions and human checkpoint decisions must remain distinguishable in the durable record.
