# DSH TeamFlow 0.2.0

This major feature update introduces personal reusable workflow templates. Package: `@yogurtss/dsh-teamflow`. This fork is distributed from GitHub/local tarballs; this change does not publish to npm.

## Personal Gallery

- A chat-header Teamflow entry opens the workbench without a slash command. New chats start in Gallery, or can switch to an empty workflow.
- Cards show a graph preview, applicability, tags, roles, tasks, human checkpoints, and version. Search/filter, detail, duplicate, edit, soft-delete, and save-as-new-version are supported.
- Save an existing workflow with AI-assisted generalization and explicit human review. Archived workflows can be exported manually; restore before opening a new extraction conversation.
- The personal library defaults to `~/.dsh-teamflow/templates`; `templateDirectory` overrides it. It is local to this user and shared across projects, without a public shop or cloud sharing.

## Reusable task contracts

Each task has `general` and `specific` layers, each containing three text fields: `requirements`, `deliverables`, `acceptance`. Generic member instructions can have an instance-only supplement.

Applying copies the selected version and retains all roles, nodes, dependencies, and human checkpoints. It does not copy sessions, provider/model settings, results, history, or approvals. Current Captain model routing is resolved anew. An isolated configuration conversation uniformly proposes all instance tasks. Review/edit and confirm before starting; unresolved adaptation issues block execution and keep their nodes visible.

Changing generic requirements affects only the instance and requires reviewing its configuration. Saving a new template version does not update existing instances. Template writes are atomic and serialized across processes; optimistic version checks prevent silent overwrites. Existing single-layer tasks remain valid and can be converted explicitly. Extraction must remove old project-specific details before reuse.

## Validation and limits

- TypeScript server/client checks and production build.
- 79 targeted template, workflow, draft and proposal tests.
- Packaged artifact through the real Harness `0.2.1-rc.2` CLI/Loader, authenticated HTTP routes, isolated discussions, scheduler and task execution. Only the external model is scripted. Verified extraction, immutable versions, fixed-graph adaptation, human confirmation, execution and native-discussion cold recovery.
- Persisted credential-free composition snapshot: `scripts/fixtures/snapshots/teamflow-template.json`. Run `node scripts/template-runtime-verify.mjs <package.tgz> <new-report-directory>` with the repository-pinned dependencies installed.
- Browser interaction checked direct entry, card/detail, applying, editing/confirming task requirements, extraction draft, tags and saving a new card.
- Broad repository regressions were run. The existing installed-bin file-symlink test requires Windows privileges unavailable here; it was explicitly skipped in a follow-up run. Directory-link fixtures use Windows junctions. No claim of a completely green unmodified full-suite command is made.
- This update has not been tested with a live paid model or across every host in the inherited compatibility matrix. Earlier desktop/Web reports describe previous versions, not validation of this feature.

No template automatically starts work or approves a human checkpoint. Maximum template size is 32 roles / 32 task nodes; the configured member limit also applies when importing.
